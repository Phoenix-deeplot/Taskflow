## 二、阶段 A：本地 Runner

### 领域层接口（Claude 先冻结，Codex 按此对接口写路由和 Runner）

只增不改现有方法签名。新增：

| 方法 | 语义 |
|---|---|
| `dispatchTask(taskId, { overrideReason?, expectedRevision? })` | 与 `startTask` 同样的校验和快照，但 Run 的状态是 `pending`，等 Runner 领取；任务进入 `working` |
| `claimRun({ runnerId, capabilities?, leaseSeconds = 60 })` | 原子领取一个 `pending` 的 Run（跳过文件范围冲突的），返回 `null` 或 `{ run, task, snapshot, leaseToken, leaseUntil }`。`leaseToken` 只在此刻返回一次，库里只存哈希 |
| `heartbeat(runId, leaseToken, { leaseSeconds? })` | 续租；返回 `{ leaseUntil, cancelRequested }`；令牌不对或已过期抛 `LEASE_LOST` |
| `appendRunEvent(runId, leaseToken, { eventId, type, message, data? })` | 进度 / 日志摘要；同一 `eventId` 重复提交只记一次 |
| `submitResult` / `reportFailure` | 新增可选项 `leaseToken`、`idempotencyKey`；对 Runner 的 Run 必须带令牌；重复提交返回第一次的结果 |
| `cancelRun(runId, { reason })` | 用户取消；Runner 在下次心跳得知 |
| `expireLeases()` | 把租约过期的 Run 置为 `worker_lost`，任务回到 `queued` 并记录原因，释放文件锁；返回受影响的 Run |
| `addArtifact(runId, leaseToken, { kind, uri, checksum, sizeBytes, metadata? })` / `listArtifacts(runId)` | 产物只存引用和摘要，大文件不进库 |

Run 状态扩为：`pending`、`running`、`succeeded`、`failed`、`cancelled`、`worker_lost`。V1 的手动流程（`startTask` 直接 `running`）保持不变。

### 给 Codex 的对接速查

**领域层方法**（`createWorkbench(db)` 返回，签名以下为准）：

| 方法 | 返回 | 说明 |
|---|---|---|
| `dispatchTask(taskId, { executorType?, overrideReason?, expectedRevision? })` | `{ task, run, snapshot }` | `run.status = "pending"`；`executorType` 缺省取任务上的值，`manual_handoff` 会被拒（400 `INVALID`） |
| `claimRun({ runnerId, capabilities, leaseSeconds? })` | `null` 或 `{ run, task, snapshot, leaseToken, leaseUntil }` | `capabilities` 是该 Runner 能执行的执行器类型数组；`leaseToken` 只返回这一次 |
| `heartbeat(runId, leaseToken, { leaseSeconds? })` | `{ leaseUntil, cancelRequested, cancelReason }` | 租约 5 秒到 1 小时，默认 60 秒；`cancelRequested` 为真时 Runner 应停止并调用 `ackCancel` |
| `appendRunEvent(runId, leaseToken, { eventId, type, message?, data? })` | `{ duplicate }` | 同一 `eventId` 只记一次 |
| `submitResult / reportFailure(runId, { …, leaseToken, idempotencyKey? })` | 同 V1 | Runner 的 Run 必须带令牌；同一 `idempotencyKey` 重试返回第一次的结果 |
| `cancelRun(runId, { reason })` / `ackCancel(runId, leaseToken)` | `{ run, task, cancelled }` / `{ run, task }` | 等待中的 Run 立即取消；运行中的 Run 先标记，Runner 下次心跳得知后确认 |
| `expireLeases()` | 被回收的 Run 数组 | 也会在每次 `claimRun` 开头自动执行，所以不依赖定时器；建议 Runner 服务端每分钟调用一次，让状态及时刷新 |
| `addArtifact(runId, leaseToken, { kind, uri, checksum?, sizeBytes?, metadata? })` / `listArtifacts(runId)` | 产物 / 数组 | 只存引用 |
| `proposeSplit(workbench, requirementId, provider, { maxTasks?, timeoutMs? })`（`server/split.mjs`，**异步**） | 草稿 | 调模型；失败会记事件、不留草稿 |

**错误码与建议的 HTTP 状态**（都是 `WorkbenchError`，`error.status` 已带正确值，路由层照常映射即可）：

| 错误码 | 状态 | 含义 |
|---|---|---|
| `LEASE_INVALID` | 401 | 令牌缺失或不对 |
| `LEASE_LOST` | 409 | 租约过期、Run 已被回收或取消，Runner 必须停止 |
| `STALE_DRAFT` | 409 | 拆分草稿基于的需求版本已变 |
| `SECRET_IN_INPUT` | 400 | 需求或全局上下文里疑似有密钥，已拒绝发给模型 |
| `TIMEOUT` / `AUTH` / `RATE_LIMIT` / `BAD_RESPONSE` / `PROVIDER_ERROR` | 504 / 502（默认） | 模型调用失败，见 `ProviderError`；`retryable` 表示可重试 |

**需要注意的三点：**

1. **Run 有了新状态** `pending`、`worker_lost`。`legacy-state.mjs` 的 `syncTaskStatus` 现在只在 `running` 的 Run 上提交结果 / 报告失败；派发给 Runner 的任务（`pending` 或 Runner 持有的 `running`）不应由页面兼容层去改，页面对这类任务只读并显示状态。
2. **提供方只需实现一个函数**：`complete({ system, input, schema, signal }) → { json, usage, model? }`，抛 `ProviderError`。其余（提示词、模式校验、超时、取消、密钥拦截、草稿落库）已在 `proposeSplit` 里。没有密钥时用 `createScriptedProvider({ replies: [...] })` 做界面和路由测试。
3. **密钥**：只在网关内部读取，不得进入 `system / input / usage`、事件、导出或日志；`proposeSplit` 会在发出前扫描输入，疑似密钥直接拒绝。
